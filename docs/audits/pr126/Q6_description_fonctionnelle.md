# Q6 — Functional description

| Functional aspect | Description | Main files | Uncertainties |
|---|---|---|---|
| Problem solved | Prevent vanilla production from creating ModeU5 economic value without passing through consumable, transferable, or losable stock | `modeu5_stock_effects.txt`, `modeu5_void_economy_effects.txt` | Depends on vanilla production exposure confirmed by TECH-01 |
| Main economic logic | Production → stock admission → possible rejection → frozen US-00 facts → demand/consumption → decay → finalization/next penalty | `modeu5_stock_on_actions.txt`, `modeu5_void_economy_effects.txt`, `modeu5_stock_demand_resolver_effects.txt` | Detail level varies between normal/performance mode |
| Normal mode | More complete traversal and richer diagnostics for country×market×good records | `modeu5_performance_effects.txt`, stock/void/demand effects | To confirm through a long test in a large campaign |
| Performance mode | Uses sparse caches, active market lists, and supplier pruning | `modeu5_performance_effects.txt`, generated adapters | Additive lists must be monitored |
| Sparse supplier cache | Reduces supplier scans by visiting only active or relevant markets/goods | `modeu5_market_country_cache_effects.txt`, `modeu5_performance_effects.txt` | Actual cost depends on campaign size and rebuilds |
| Known limits | Some vanilla values are missing or remain fallbacks; optional packages are not runtime toggles | `TECH-01_engine_exposure_matrix.md`, `MODULE_OPTION_MODEL.md` | Any `TO_TEST` exposure must remain blocking or have an accepted fallback |
| Player-facing behavior | The player should see a less void economy: overproduction rejected/stored, consumption satisfied or unsatisfied, deferred penalties | Localization/debug, test docs | Full UI outside MVP |

## Canonical business flow

```txt
1. Vanilla or fallback estimates production.
2. ModeU5 tries to admit that production into stock.
3. Capacity determines added vs rejected.
4. US-00 freezes the month's facts: produced / added / rejected / overproduction inputs.
5. US-10 reads stock to satisfy consumption or transfer.
6. Decay acts on remaining stock.
7. US-00 finalizes carryover from frozen facts, not from post-decay stock.
8. Validation/reconciliation checks the stock invariant.
```

## Functional guardrails

| Situation | Rule |
|---|---|
| Stock modified | Use the central operators. |
| Vanilla production read | Check TECH-01 and accepted fallback. |
| US-00 modified | Separate ingestion facts and finalization/carryover. |
| US-10 modified | Keep same-market consumption and inter-market transfer separate. |
| Performance modified | Declare owning scope, cache owner, rebuild, and reset policy. |
| Code generated by good | Use `tools/modeu5_goods.sh`, templates, and existing validators. |

## Expected player result

```txt
recognized production <= readable vanilla production
useful stock <= available capacity + lifecycle-authorized over-cap
satisfied consumption <= accessible stock
inter-market transfer <= transferable stock and accepted rules
next penalty = function of the month's US-00 facts, not of a late reconstructed state
```

Any UI or debug added later must make these relations verifiable without inventing a new source of truth.
