# Q8.7 shadow comparison — impact on Q1 to Q5

## Purpose

This note connects the Q8.7/F7 shadow-comparison increment back to the earlier PR126 audit questions Q1 to Q5.

The change is intentionally documentation/proof-track only. It does not change live runtime, does not mutate stock, and does not replace the monthly dispatcher.

## Q1 — File architecture

The Q8.7 shadow-comparison increment keeps the same package boundary:

```txt
packages/modeu5_core_tests
```

The new runtime-facing proof surface remains in the test package:

```txt
packages/modeu5_core_tests/in_game/common/scripted_effects/modeu5_q8_7_shadow_dispatcher_effects.txt
packages/modeu5_core_tests/in_game/events/modeu5_q8_7_shadow_debug_events.txt
packages/modeu5_core_tests/in_game/localization/modeu5_core_tests_l_english.yml
```

Consequence for Q1:

```txt
No production package is reorganised.
No live dispatcher file is moved.
No stock-source file is touched.
The Q8.7/F7 proof remains isolated from gameplay runtime.
```

This is aligned with the Q1 principle that architecture changes should make ownership clearer without mixing test probes into production state ownership.

## Q2 — Cache system

The probe compares two market ownership surfaces:

```txt
native global market pass:
  every_market_in_world

legacy market-center workaround:
  every_country
    -> every_market_center_in_country
```

It records unique market membership in temporary diagnostic global lists and compares both sets.

Consequence for Q2:

```txt
The current countries_present_in_market work cache is not replaced.
The probe does not introduce durable per-market country-list storage.
The probe does not reuse or persist market-country cache results.
```

The Q2 cache decision remains unchanged: `countries_present_in_market` is still a work cache, not a source of truth. Q8.7 only tests whether a future global market owner can become a cleaner owner for that cache.

## Q3 — Redundant code / duplication risk

The purpose of the shadow comparison is to reduce a future duplication risk before any live switch.

Current workaround shape:

```txt
country pulse
  -> every_market_center_in_country
     -> market-local work
```

Target shape if future Q8.7/F7 proofs pass:

```txt
global monthly market pass
  -> every_market_in_world
     -> market-local work
```

Consequence for Q3:

```txt
This PR does not remove duplicated orchestration yet.
It adds a proof that future code can delete or simplify the market-center ownership workaround safely.
```

A PASS means the market-center workaround and native global market pass see the same market set in Normal Mode. That is a prerequisite before deleting old ownership/duplicate-prevention code.

## Q4 — Loop/performance structure

Q4 identified dangerous loop shapes. The probe explicitly checks the ownership boundary without entering heavy work.

The dangerous shape remains forbidden:

```txt
every_country
  -> every_market_in_world
     -> present countries
        -> goods
```

The Q8.7 shadow comparison does not do that. It compares:

```txt
every_market_in_world
```

against:

```txt
every_country
  -> every_market_center_in_country
```

and stops at set comparison.

Consequence for Q4:

```txt
No US-00 loop is run.
No US-10 loop is run.
No generated-good loop is run.
No stock mutation loop is run.
```

This proves an outer-loop ownership condition only. It does not claim the full Q4/Q8 runtime rewrite is complete.

## Q5 — Global logical flow

Q5 is the most affected conceptually.

The long-term target flow becomes clearer:

```txt
1. country preparation pass
2. global market-local pass
3. country trade-owner pass
4. validation / reconciliation pass
```

This PR proves only a small part of step 2:

```txt
global market-local pass can enumerate the same market universe as the old market-center owner workaround, in Normal Mode, without stock mutation.
```

Consequence for Q5:

```txt
Current monthly flow is unchanged.
Trade position is unchanged.
US-00 before US-10 ordering is unchanged.
Validation/reconciliation position is unchanged.
```

The next Q8.7/F7 proof should compare the performance-mode / human-relevant market set before any live flow is moved.
